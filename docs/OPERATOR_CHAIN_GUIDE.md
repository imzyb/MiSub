# MiSub 操作符链 (Operator Chain) 完全指南

MiSub 的核心灵魂在于其强大的节点处理引擎。从 v2.5.0 版本开始，我们引入了**操作符链 (Operator Chain)** 架构，将节点转换逻辑从硬编码升级为高度可定制的流式管道。

---

## 1. 核心概念：什么是操作符链？

操作符链类似于工业生产流水线。每一个“操作符 (Operator)”都是一个独立的加工工序：
1. **输入**：原始节点列表（来自机场订阅或手动输入）。
2. **加工**：按照您设定的顺序，依次执行过滤、重命名、排序等操作。
3. **输出**：最终生成的、符合您需求的干净节点列表。

> [!TIP]
> **继承机制**：在“订阅组”中，如果您不配置任何操作符，系统将自动使用“全局设置”中的默认链。如果您在订阅组中单独配置，则会完全覆盖全局设置。

---

## 2. 内置操作符详解

### 🛒 过滤节点 (Filter)
通过多种维度精准控制节点的去留。
- **协议限制**：仅保留 vless, hysteria2 等特定协议。
- **地区限制**：通过内置算法识别香港、日本等常用地区。
- **包含/排除正则**：使用正则表达式匹配节点名称。
- **安全规则过滤**：使用声明式条件组合自定义过滤逻辑。
- **精简模式**：自动剔除已过期的、流量超限的或名称中含有“流量额度”等无效节点。

### 🏷️ 节点重命名 (Rename)
重塑节点名称，使其在客户端中整齐划一。
- **正则替换**：将 `香港 01` 替换为 `HK-01`。
- **模板重写**：支持占位符，如 `{emoji}{region}-{protocol}-{index}`。
  - `{emoji}`: 自动添加国旗。
  - `{regionZh}`: 中文地区名。
  - `{index}`: 自动递增序列号。

### 🔢 节点排序 (Sort)
定义节点的优先级。可以添加多个排序条件（Weight），按照先后顺序作为主次关键字。
- **常用排序**：按地区升序 -> 按协议升序 -> 按名称升序。

### 🧹 智能去重 (Dedup)
基于服务器地址和端口的指纹识别，自动合并多份订阅中重复的节点，保持列表清爽。

## 3. 🛡️ 脚本转换 (Script Transform)

脚本转换提供两种模式：

### 沙箱 JavaScript

旧版 `return ($nodes) => { ... }` 同步脚本可继续使用，但代码在隔离的
QuickJS/Wasm 运行时内执行，而不是在 Worker 主环境中执行。

- 脚本只能访问节点的 JSON 副本、`$proxies` / `$nodes` 和有限的 `$context`。
- 不提供 `fetch`、KV/D1、环境变量、Cookie、Node.js API 或 Worker 全局对象。
- 每次执行均限制脚本大小、节点数量、内存、栈、运行时间和输出大小。
- 返回值必须是合法的节点对象数组；异常、超限和无效结果会保留原节点。
- 仅支持同步脚本。

远程脚本 `url` 不会加载。请先审核脚本，再把代码粘贴到沙箱编辑器。

### 安全规则

安全规则使用声明式 JSON，不执行任意 JavaScript。当前支持：

- `filter`：按字段、文本或正则条件过滤节点。
- `rename`：通过 `when` / `unless` 条件重命名，可使用 `groupBy` 独立编号。
- `sort`：按规则生成的数值或文本字段稳定排序。

编辑器内置“地区/协议规范化”预设，可将常用地区、协议和 Cloudflare
优选节点规范为 `🇭🇰HK-HY2-1`、`☁CF-US-1` 等名称。

## 4. 常见问题 (FAQ)

**Q: 我应该把操作符放在全局还是订阅组？**
A: 如果大部分机场的处理方案一致，建议放在“全部设置”。对于特殊的“直连组”或“流媒体专线”，可以在订阅组中单独定制。

**Q: 操作符的执行顺序有影响吗？**
A: **非常有影响！** 通常建议的顺序是：
`去重 (Dedup) -> 过滤 (Filter) -> 重命名 (Rename) -> 排序 (Sort)`。
先过滤掉不需要的节点，再对剩下的节点进行重命名和排序，效率最高。
