# 订阅组链接与「订阅 ID」

本文说明订阅组（profile）的对外链接如何生成、如何解析、如何重置。相关 issue：<https://github.com/imzyb/MiSub/issues/538>。

## 三层标识

| 字段       | 生成                                    | 可变       | 可路由         | 用途                                                           |
| ---------- | --------------------------------------- | ---------- | -------------- | -------------------------------------------------------------- |
| `id`       | 创建时 UUID                             | 永不       | 否             | 主键、`subProfiles` 引用、外部 API、下载计数 key、访问日志归属 |
| `linkId`   | 新组创建时生成；存量组升级时补成原 `id` | 重置时轮换 | 是（次优先）   | 系统生成的「订阅 ID」                                          |
| `customId` | 用户手填，可空                          | 可改可清   | 是（最高优先） | 用户自定义的「订阅 ID」                                        |

对外链接形如 `/{profileToken}/{订阅 ID}`，其中「订阅 ID」= `customId || linkId`。

字段名 `linkId` 是代码内部命名，界面上统一显示为「订阅 ID」（界面「订阅组」对应代码 `profile`，同理）。

## 解析规则

公开入口（订阅链接、公开预览）统一走 `resolvePublicProfile`：

1. 先按 `customId` 匹配（大小写不敏感）；
2. 未命中再按 `linkId` 匹配，但**仅限没有设置 `customId` 的组**；
3. 最后仅当该组既无 `customId` 也无 `linkId` 时，才回退用 `id`（兼容迁移尚未落库的窗口）。

内部入口（嵌套子组、外部管理 API、后台引用）走 `resolveInternalProfile`，三者都认，保持原有内部语义。

## 行为矩阵

| 组状态                        | 可访问                | 说明                      |
| ----------------------------- | --------------------- | ------------------------- |
| 存量组升级后（`linkId = id`） | `/{token}/{id}`       | 升级不断链                |
| 新组（`linkId` 独立随机）     | `/{token}/{linkId}`   | 与主键解耦                |
| 设了 `customId`               | `/{token}/{customId}` | `id` 与 `linkId` 均不可达 |
| 清空 `customId`               | `/{token}/{linkId}`   | 存量组此时等于原 `id`     |
| 重置                          | `/{token}/{新linkId}` | 旧链接立即失效，主键不变  |

## 计数与日志

- 下载计数 key 恒为 `misub_profile_download_count_{id}`，改自定义 ID 或重置链接都不会掉档；旧 key（曾用 `customId`）在首次读取时自动迁移。
- 访问日志的匿名标识基于 `id` 生成，同一个组永远同一串，不受链接变更影响。

## 「订阅 ID」校验

- `customId`：`^[a-z0-9_-]{2,32}$`；`linkId`：`^[a-z0-9_-]{2,64}$`（UUID 36 位）。
- 保存前统一转小写；全局互斥，且不得与其他组的主键相同。
- 不得使用保留字（`sub`、`api`、`assets`、`cron`、`login`、`logout`、`_/`main`等）或`mytoken`/`profileToken`。
- 校验在管理端保存接口与外部管理 API 双向执行（`functions/modules/profile-alias.js`）。

### 存量豁免

`customId` 在 2025-06 上线时没有任何长度/字符集限制，库里可能存在超长或含非法字符的历史值（例如 128 位）。校验是对**整个列表**执行的，若不特殊处理，一条历史值会让用户保存**任何**无关改动都返回 400。

因此校验按「值是否被改动」区分：

- 值与会话前已落库的值一致（小写归一化后）→ 视为存量值，**跳过字符集/长度/保留字检查**，旧链接继续可用；
- 值被改动或为新增 → 必须满足规则，否则返回 `profile_alias_invalid`；
- **冲突检测对存量值同样生效**：两个组共用一个链接本身无法解析。

实现上通过 `validateProfileAliases(profiles, { previousProfiles })` 传入已落库列表作为基线；全量保存与 diff 保存都会加载基线。界面可用 `findLegacyInvalidAliases()` 找出仍需手动修复的历史值。

## 迁移

`migrateProfileLinkIds` 在订阅请求入口与管理端读取接口执行，规则为 `if (!profile.linkId) profile.linkId = profile.id`，幂等且永不覆盖已重置的值。恢复旧备份后会在首次请求时再次补齐。

## 重置的语义边界

重置只更换对外链接，不改变主键；重置过的组即使清空 `customId`，链接也回到 `linkId` 而不是最初的 `id`——这是有意的：撤销过的链接不能因为清空字段而复活。
