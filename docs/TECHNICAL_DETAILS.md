# MiSub 后端技术细节 (Technical Details)

本文档面向使用与运维 MiSub 的用户，说明订阅生成、操作符、存储、节点持久化与定时刷新等环节的实际行为。文中只描述可观察到的行为与开关，不涉及具体代码实现。

---

## 1. 节点处理流水线 (Processing Pipeline)

一次订阅输出的生成会依次经过以下几个阶段。机场订阅、手动节点与嵌套子订阅组都走同一条链路，最终输出与持久化保存的内容保持一致。

1. **目标解析 (Target Resolution)**：按订阅组解析出本次要输出的机场订阅、手动节点，以及嵌套引用的子订阅组（最多嵌套 3 层）。订阅组可以用自定义标识、公开链接标识或内部编号引用，对外入口按“自定义标识 > 公开链接标识 > 内部编号”的顺序确定。
2. **节点来源 (Node Source)**：
    - 开启 D1 节点持久化（见第 5 节）时，输出直接读取已保存的节点快照；还没有快照的订阅会在本次请求中补建，一次请求最多补建 3 个，避免拖慢响应。
    - 未开启持久化时实时拉取订阅；上游失败或没有取到有效节点时，回退到上一次可用的保护性缓存。
    - 快照在保存前已经应用过操作符与过滤，输出时不会重复应用，避免改名类操作被叠加两次。
3. **清洗与过滤 (Cleaning / Filtering)**：修正节点链接中损坏的 URL 编码，并按订阅组填写的过滤规则筛选节点。规则文本中 `keep:` 开头的行（或 `---` 之后的内容）为包含规则，其余行为排除规则，两类规则可同时生效；匹配维度为协议、名称与地区。
4. **算子链 (Operator Chain)**：按配置顺序执行筛选、改名、脚本、排序与去重操作符，详见第 2 节。
5. **格式生成 (Generator)**：根据请求的 User-Agent 选择 Clash / Sing-Box / Surge / Loon / QuanX / Egern 内置输出格式，或使用自定义模板渲染。

手动节点与机场订阅共用同一套转换流程；节点分组、手动节点名称前缀与分组名前缀也在此阶段统一补齐。

## 2. 操作符运行引擎 (Operator Runner)

操作符按配置顺序依次作用于节点列表：每个操作符读取当前节点列表并输出一份新列表，最终结果再写回订阅输出。MiSub 支持五类操作符：筛选、改名、脚本、排序、去重。

### 脚本算子与受限表达式 DSL (Script Sandbox)

脚本算子只接受受限的声明式步骤列表（JSON 格式），**不再执行任意 JavaScript，也不再支持从远程地址加载脚本**。旧版本中填写的脚本代码或脚本地址不会被运行，只保留原有节点并给出告警。

受限 DSL 目前支持两类步骤：

- **筛选**：按字段比较条件过滤节点。
- **改名**：按模板渲染生成新名称。

模板只能引用节点字段、节点序号与输出目标等有限上下文，并提供大小写转换、首字母大写一类少量文本辅助能力，不暴露任意运行环境。因此脚本算子无法执行任意代码、无法访问网络，也不会出现死循环；配置可审计、结果可复现。

从旧版本升级时，原来的“脚本改名”会自动迁移成等价的受限步骤；“脚本过滤”与“精简模式”没有等价的操作符，迁移时会提示未迁移，需要按新的 DSL 手动重写。升级后请检查对应订阅组的输出是否符合预期。

### 排序与去重 (Sort / Dedup)

- **排序**：可选择名称、地区、协议、分组、端口、服务器地址等排序键，地区与协议还支持自定义顺序。
- **正则置顶优先级**：以正则作为排序键时，自定义顺序中的正则按书写顺序置顶，始终由高到低，不受正序 / 倒序设置影响。
- **去重**：默认按“协议 + 服务器地址:端口”判断重复，冲突时保留名称更长的节点。

### 性能优化

- **结果稳定**：操作符只读取原始节点并生成新列表，不会改动已有数据，同一个订阅多次输出的结果一致。
- **大节点量可用**：排序键与自定义顺序只在执行开始时解析一次，节点数量较大时排序与去重也不会明显变慢。

## 3. 存储适配层 (Storage Adapter)

MiSub 支持 KV 与 D1 两种存储方式：

- 系统按当前设置与已绑定的存储自动选择存储方式；两者都不可用时进入只读的“无存储”状态，页面仍可打开，但不会保存数据。
- KV 方式按类别整体保存订阅、订阅组与设置；D1 方式按条保存，每条记录带更新时间，集合读取带短时间的进程内缓存（写入后立即失效），避免频繁查询数据库。
- 设置项单独缓存，修改设置后相关缓存立即失效。
- 启动或升级时，系统会识别旧版 D1 数据结构（包括早期的单行数据）并迁移到新的行级结构；迁移幂等，可重复执行。
- 节点持久化使用同一套存储能力：每个机场订阅一行快照，节点较多时自动分片保存，详见第 5 节。

写入行为：批量写入尽量合并为一次提交，减少“写一半”的状态；快照写入按“后写优先”保护，晚到的旧结果不会覆盖更新的结果。KV 没有事务能力，多类数据按顺序写入，失败时由调用方重试。

## 4. 节点解析逻辑

系统能从各种订阅文本中识别节点，解析分三步：

1. **候选提取**：按协议前缀与常见的 Base64 / YAML / JSON / 逐行文本格式扫描出可能的节点串。
2. **格式分发**：识别 Clash YAML、Sing-Box、v2rayN、Surge / Quantumult X 逐行格式以及 URL Scheme 列表，并分别转换为统一的节点形式。
3. **协议提取与归一**：逐行解析协议参数；SS2022 节点会校验并尽量自动修复参数，最终统一为同一种节点表示。加密算法不在白名单内的节点会被丢弃，避免输出不可用配置。

## 5. 节点持久化 (Node Persistence)

开启条件（需同时满足）：已绑定 D1 数据库、存储类型选择 D1、设置中开启“节点持久化”。

- **保存内容**：每个机场订阅保存一份节点快照，包含节点列表、节点数、订阅流量信息、最近成功时间、最近尝试时间与最近一次错误；节点较多时自动分片保存，每片约 256KB、最多 80 片。旧数据库在首次使用时自动建表并补齐缺失字段，无需手工迁移。
- **配置指纹**：快照会记录当时影响节点结果的配置（订阅地址、自定义 User-Agent、拉取代理、空格处理、排除规则、操作符与节点转换设置）。配置变化后，下一次输出会重新拉取并覆盖该订阅的快照，保证输出与最新设置一致。
- **刷新与保护**：对同一订阅的刷新不会并发执行；刷新失败只更新错误信息与尝试时间，已有节点继续可用，并在短时间内不再重复拉取同一机场。上游返回空节点或节点数骤降视为失败，不会用空快照覆盖旧数据。
- **启用即全量回填**：开启持久化时会自动为所有远程订阅建立快照，分批进行（每批 6 个），页面关闭后仍会继续，全部完成后由定时刷新接续。
- **定时刷新**：按“自动更新间隔”判断哪些机场到期需要刷新，跳过已暂停自动更新的机场；刷新在后台异步执行，不阻塞页面请求。

## 6. 订阅标识与组合订阅嵌套 (Profile Identity & Nesting)

- **三层标识**：订阅组可用三种方式引用——用户自定义标识、系统生成的公开链接标识、内部编号。对外访问按“自定义标识 > 公开链接标识 > 内部编号”的顺序解析；内部引用（嵌套子组、外部管理 API、后台任务）宽松匹配。
- **标识规则**：自定义标识与公开链接标识只允许小写字母、数字、下划线与连字符；自定义标识长度 2–32，公开链接标识 2–64，保存前统一转小写；两者在全站范围内互斥，不能与其它订阅组重复。公开链接标识由系统生成。
- **退役与兼容**：为订阅组设置自定义标识后，原来的编号与公开链接标识不再可访问；升级时会为存量订阅组补齐公开链接标识（幂等），旧订阅链接不会断链；重置公开链接标识后旧值立即失效。
- **组合订阅嵌套**：订阅组可以通过“子订阅组”引用其它订阅组，最多嵌套 3 层；保存时会检测循环引用，形成环的配置无法保存。
- **包含与剔除规则共存**：一条规则文本即可同时写包含与排除规则（`keep:` 行或 `---` 之后为包含，其余为排除）。
- **单机场禁用自动更新**：只有显式关闭“自动更新”的机场才算暂停（历史数据默认开启）。自动到期刷新、批量刷新与外部 API 批量刷新都会跳过暂停的机场；定时刷新入口则是独立于自动更新间隔的强制刷新通道。

## 7. 外部管理 API 与 WebDAV 备份

- **外部管理 API**：基址 `/api/ext/v1`，请求需带 Bearer Token，且需在设置中开启外部 API。
    - 订阅：`/subscriptions`、`/subscriptions/validate`、`/subscriptions/batch-refresh`、`/subscriptions/:id`、`/subscriptions/:id/refresh`
    - 手动节点：`/manual-nodes`、`/manual-nodes/validate`、`/manual-nodes/:id`
    - 订阅组：`/profiles`、`/profiles/:id`、`/profiles/:id/preview`、`/profiles/:id/refresh`、`/profiles/:id/(subscriptions|manual-nodes)`
    - 列表接口支持分页，错误返回统一结构；开启节点持久化时，列表与详情中的节点数与流量信息以保存的节点快照为准。
- **WebDAV 备份**：路由 `/api/backup/webdav/{status,test,run,list,restore}`，另有本地 `/api/backup/{export,restore}`。备份按业务域导出（格式标识 `misub-backup` v1，可选择只备份数据或同时备份设置），默认文件名 `misub-backup-{datetime}.json`，时间按北京时间（UTC+8）生成，默认保留 7 份；WebDAV 凭据与运行时密钥不会写入备份内容。

## 8. 定时任务与刷新口径

- **唯一刷新链路**：`/cron` 与登录后的 `POST /api/cron/trigger` 都走同一条“节点快照刷新”，旧的定时实现已删除。`/cron` 使用设置中的 Cron 密钥校验（`Authorization: Bearer <secret>` 或 `?secret=`）。`/cron-dashboard` 页面不再提供触发接口，其 POST 请求返回 405；手动触发请使用登录后的 `/api/cron/trigger`。
- **执行条件**：定时刷新只受开关与存储条件影响——需要开启 Cron，并且已开启 D1 节点持久化。没有并发数、超时时间、并行开关一类的可调参数；实际执行为并发 6、单订阅超时 15 秒。
- **管理接口**：`/api/cron/status` 返回持久化开关与执行状态；`/api/cron/trigger` 校验持久化后触发节点快照刷新，并顺带运行已配置的定时任务。
- **刷新口径统一**：定时刷新、手动刷新、批量刷新以及外部管理 API 的刷新，最终都写入同一份节点快照；读取时再从快照回填节点数与流量信息，避免各通道各写一份导致数据不一致。
